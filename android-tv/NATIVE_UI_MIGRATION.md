# 原生界面迁移约束

**当前状态（0.4.4）**：用户要求修复投影仪与模拟器界面不一致，检查确认投影仪桌面图标仍启动旧网页，模拟器测试使用原生复刻。现已统一为此前复刻、通过用户实机确认的界面，桌面启动不再要求预览参数。布局和遥控逻辑继续保留；仅调试版显式 `legacy_web_ui=true` 可对照旧网页。业务层仍未全部迁移到 Kotlin。

以下为 0.3.2 预览阶段的约束与历史记录，关于默认入口尚未切换的描述仅适用于该阶段。

用户要求保留此前已确认的界面设计和操作逻辑。当前默认入口恢复为原有的独立电视界面；APK 0.3.2 延续 0.3.0 的布局与遥控器行为，仍不依赖电脑服务器。

本次尝试的新原生布局没有获准作为默认界面。`NativeTvActivity` 是按原版复刻的验证入口：发布版清单中 `enabled=false`；仅调试版启用，且不对外导出。启动器仍指向原来的 `MainActivity`，只有显式传入 `native_preview=true` 才打开预览。不能把这一阶段报告成原生界面迁移已完成。

后续迁移必须遵守：

- 首页的布局、搜索栏、搜索历史和影片卡片沿用原设计，不擅自增加“继续观看”网格或改变信息层级。
- 影片确认后的打开/播放行为沿用原逻辑，不强制增加新的详情步骤。
- 播放页保留原控制栏布局、自动收起时机、焦点顺序和遥控器状态机。
- 保留透明缓冲提示和较小的网速字体。
- 选集和换源沿用此前确认的布局、留白与确认步骤。
- 原生化只替换底层实现；先与旧版逐屏、逐键对照，确认一致后才能替换默认入口。

实验阶段已经验证过原生网格焦点、搜索结果、Media3 视频输出、暂停和倍速；这些验证不代表新布局已被用户接受。

## 原界面复刻预览

在项目根目录运行：

```bash
./android-tv/run_local_tv_emulator.sh --native-preview
```

省略参数即可恢复原有界面。脚本只对 `emulator-5554` 安装和启动，覆盖安装保留数据，不会更新投影仪，也不会启动电脑服务器。

已实现的复刻：

- 首页沿用原搜索栏、五列搜索历史、五列影片卡片及整页滚动；遥控器确认卡片直接播放，触摸仍可查看来源及集数。
- 播放页沿用顶部片名、底部渐变控制栏与透明缓冲网速提示；左右键预览、确认提交、返回取消，控制栏中的左右键只移动焦点。
- 选集保持底部面板、八列剧集、正倒序切换和当前集初始焦点；设置保持原倍速、画面比例、自动连播及广告过滤行。
- 换源保持双列列表、右侧封面/响应速度/可用集数/确认按钮；焦点浏览只更新预览，失败来源支持重新检测，关闭会取消检测请求。
- 片源管理保留四列来源和横排输入表单；与旧入口共用现有来源、搜索历史和播放进度。

控件及焦点由 Android View 绘制和处理，播放继续使用 Media3。包内不可见的数据页暂时复用既有搜索、解析和 IndexedDB，业务层尚未完全迁移到 Kotlin。

## 验证范围

在 Android 11 / 1920×1080 模拟器已验证：旧历史启动与搜索、方向键选片、确认直接播放、720P 实际出画面、暂停、控制栏/进度条/选集的焦点切换、设置菜单切换、换源布局及检测结果。暂停时实测两次右键只预览，播放位置保持 44.567 秒；确认后变为 64.567 秒，再次预览后返回取消仍为 64.567 秒。

原生单元测试覆盖同网页的焦点距离规则、返回层级、上下键/确认/菜单行为与跳转边界；业务协议测试覆盖进度恢复、清空搜索历史、关闭取消、换源阶段顺序和失败重测。

原生预览已完成模拟器与 JMGO 的首轮操作回归，默认入口尚未切换；搜索、解析、IndexedDB 仍由不可见数据页复用，因此这里的完成范围是原生界面复刻与遥控器操作验证。业务层全部迁移到 Kotlin 尚未完成。

## 2026-10-23 实机回归（0.3.2）

设备：JMGO NS1 4K，Android 11 / API 30，1920×1080，WebView Chrome 83。覆盖安装前后逐条比较：18 条观看记录、15 条进度、4 条搜索历史完整保留；启用来源、自定义接口、订阅、广告过滤和连播设置一致。测试之后新产生的播放进度正常写回原数据库。

已完成：

- 用户在实机确认首页、视频画面和底部按钮均可见且显示正常。
- Media3 输出 720P 与 1080P；切集创建新的播放会话，选集、返回及控制栏焦点保持原逻辑。
- `check-native-playback.mjs` 使用真实 ADB 方向/确认/返回按键通过 11 项检查：出画面、下键聚焦、控制栏左右导航、左右预览、确认/取消、倍速、画面比例、上键选集、正倒序、返回焦点、恢复测试现场。
- 换源面板实机完成候选和画质检测，保留双列列表及右侧详情；确认换源保留当前集数，并使用新来源自身的保存进度。
- 补齐首页焦点光晕、播放按钮外圈、字体粗细及透明缓冲转圈；网速格式与旧版一致。
- 搜索开始时立即刷新历史，慢来源不再阻塞历史显示；修复历史排序后焦点跟错条目、未知时长仍显示快进预览、换源详情重测可重复点击的问题。
- 封面请求队列覆盖最多 300 组搜索结果，避免较早的可见封面被后续任务挤掉；已移除的卡片不再发起排队下载。

最终包实机验证了历史项从第 3 格移到第 1 格后仍保留同一条目的焦点，且片源仍在搜索时历史已刷新。

Android 构建、506 项网页测试、15 项原生单元测试与 lint 通过。JMGO 的系统截图接口在旧版和原生预览均返回黑图，因此实机视觉结论采用用户确认，其他操作通过原生控件树和播放器状态交叉检查；没有把黑截图当作视频解码失败。

默认启动仍打开此前确认的 `/tv` 界面。仅调试版可通过 `MainActivity --ez native_preview true` 进入原生预览，发布清单继续停用原生验证入口。


## 0.4.4 投影仪与模拟器入口统一

实机正在前台的组件为 MainActivity，数据页为 /tv，1920×1080 / 320dpi；先前模拟器及实机回归显式传 native_preview=true，使用 NativeTvActivity 和 /native-tv。相同 APK 的不同启动方式导致两套 UI 并存。MainActivity 现默认转交非导出的 NativeTvActivity，调试和发布清单均启用该内部组件；旧网页仅在调试版显式 legacy_web_ui=true 时进入。模拟器默认脚本同步使用同一路径，旧预览参数兼容。未更改设备分辨率、系统密度或原有布局设计。

投影仪与模拟器均为 1920×1080 / 320dpi。正常桌面启动实测均进入 NativeTvActivity，连续从普通及电视桌面重开仅保留一个原生实例。片源管理中的完成按钮、播放模式、超分开关、电脑连接按钮与模拟器控件坐标一致；从完成按钮依次向下可到模式、超分、服务器地址、片源列表，未改变任何设置。模拟器换源排序、缓存刷新和焦点 5 项回归通过，Android 构建、16 项单元测试和 lint 通过；发布清单检查确认内部原生组件可用且非导出。投影仪覆盖安装 0.4.4 / code 11，保留 49 个来源与当前超分关闭设置。实机系统截图仍不可用于视觉核验，以上一致性结论来自实际控件布局及 ADB 按键检查，报告 `.desktop-server/tv-ui-consistency.json`。

对比两台同分辨率设备的正常启动与片源管理布局：

```bash
node android-tv/scripts/check-tv-ui.mjs emulator-5554 192.168.0.107:5555
```

脚本不改片源/配对/开关设置，会重新启动应用、打开设置并移动焦点，结束返回首页。

## 0.4.5 换源面板溢出修复

用户补充照片后确认问题发生在播放换源页，上次对照首页片源管理并未覆盖该场景。实机当时共有 37 个来源；模拟器用同等规模复现，发现原先为避免焦点裁切关闭了 ScrollView.clipChildren，导致卡片持续绘制到页脚及面板外。仅比较可访问性节点坐标未能发现绘制越界。

换源正文改为有界的弹性高度，去掉外层嵌套滚动，保持原左右双列来源/详情设计。左侧滚动区和焦点光晕均按视口裁切，滚动定位保留焦点边距，顶部按钮对齐。补充来源列表到右侧操作按钮的显式焦点关系，避免最后一行只有一项时，右键误选上一行来源并改变详情。

37 来源实际截图及 ADB 检查 4 项通过，独立的排序/缓存/焦点 5 项回归通过，Android 构建、16 项单元测试和 lint 通过。已检查模拟器修复前后图像：来源卡片和焦点光晕不再覆盖页脚，滚动到底部后最后一张卡片完整可见。APK 为 0.4.5 / code 12。

安装阶段投影仪 192.168.0.107:5555 断开，ADB 返回 No route to host，ping 不可达；电脑仍为 192.168.0.113。修复包已生成，尚未成功覆盖安装到投影仪；待设备重新联网后完成实际影片换源验证。此前配置备份 `.desktop-server/projector-before-045.json`，不输出配对数据。
