# LibreTV Android TV

当前 APK **0.5.1** 已支持投影仪独立运行：界面随 APK 打包，搜索和 Media3 播放直接使用设备网络，无需电脑服务器和密码。覆盖安装保留原有记录。首页「片源管理」或菜单键可管理来源。实现、升级与限制见 [独立运行说明](STANDALONE.md)。

界面布局和遥控器操作沿用此前确认的原设计。0.4.4 将桌面图标、模拟器和重开应用统一为原生复刻入口，避免因缺少 `native_preview` 参数切回另一套网页布局。直接运行 `./android-tv/run_local_tv_emulator.sh` 即可；旧 `--native-preview` 参数仍兼容，调试对照旧网页使用 `--legacy-web`。见 [迁移记录](NATIVE_UI_MIGRATION.md)。

0.4.2 默认超分只升高一个档位（720P → 1080P、1080P → 4K），换源按原始分辨率降序并保持焦点。0.4.1 增加原始/输出分辨率、实际超分与去广告结果标注，电脑端提供可选 4K 档位。0.4.0 将可选电脑串流升级为广告分片过滤、GPU 超分和 H.264/AAC 编码（先在模拟器验证），入口仍位于原来的「片源管理」。独立直连仍为默认模式；界面及遥控逻辑保持原样。启动、配对与测试见 [电脑串流说明](../desktop-server/README.md)。

## 构建

先在项目根目录执行 `npm ci`，再安装 JDK 17 和 Android SDK 35。之后，在 Android Studio 中选择 `app` 并运行，或从 Gradle 工具窗口执行 `app > Tasks > build > assembleDebug`。也可直接使用仓库内的 Gradle Wrapper：

```bash
./gradlew assembleDebug
```

APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`。

## 当前边界

- 界面由 Android 控件绘制，APK 中不可见的 `/native-tv` 数据页复用搜索、详情、换源、画质及持久化逻辑，播放使用 Media3。普通浏览器仍使用原网页。
- 片源配置、搜索历史、观看记录保存在电视 WebView 本地。
- 同时注册 Android TV 和普通 Android 启动入口，可安装到电视盒子及常见安卓投影仪。
- 局域网 HTTP 已允许；公网部署请使用 HTTPS。
- 已完成独立点播及原生界面复刻；语音输入仍延后，搜索/解析业务暂由不可见数据页复用。

## Media3 原生播放

APK 0.2.0 引入原生视频层，支持 HLS、原始比例/裁切、倍速、快进、选集、换源、进度恢复、后台暂停及错误反馈。控制栏、焦点和透明缓冲网速提示保持现有电视样式。原生下载请求与 Cookie 处理见 [播放协议](PLAYBACK_PROTOCOL.md)。

Media3 固定为与当前 compileSdk 35 / AGP 8.7 兼容的 1.8.1，使用解码器回退。是否支持特定 4K/HDR 编码仍需实机验证。原生播放尚未使用网页分片缓存和外挂字幕选择。

验证命令（在 `android-tv` 目录）：

```bash
./gradlew assembleDebug testDebugUnitTest lintDebug
```

## 电视播放页

从 `/tv` 选片进入播放后，画面默认覆盖整个视口并保留原始比例，控制栏闲置 5 秒自动收起。片源与屏幕比例不同时会留黑边，避免裁掉字幕和画面。

| 遥控器按键 | 播放页行为 |
| --- | --- |
| 确认 | 播放 / 暂停；面板中执行当前选项 |
| 左 / 右 | 画面上预览快退 / 快进，每次 10 秒，确认后跳转；控制栏中移动焦点 |
| 下 | 呼出控制栏，可选上一集、下一集、选集、换源、设置 |
| 上 | 在画面上打开选集；控制栏中上移到进度条 |
| 菜单 / 设置（电脑 F2） | 打开倍速、完整显示 / 裁切铺满、自动连播、广告过滤设置 |
| 返回 | 先关闭面板或取消进度预览，再收起控制栏，最后退出播放 |

这套按键需要新版 APK；换源和切集均保留电视播放模式。首页菜单键打开片源管理。

# 本地电视模拟器

已配置的本机调试环境使用 Android 11（API 30）与 1920×1080 电视配置。独立版直接运行：

```bash
./android-tv/run_local_tv_emulator.sh
```

脚本会启动或复用 `LibreTV-TV-API30` 模拟器，清理旧版 `8080` 端口转发，构建调试 APK 并安装启动。模拟器的 SDK 和 AVD 都保存在 `android-tv/.android-sdk/` 与 `android-tv/.android-avd/`，不会提交到 Git。

新启动的模拟器开启硬件键盘和按键直通，设置单独保存在 `android-tv/.emulator-config/`。单击模拟器画面后，电脑方向键可用于遥控器导航，Enter 用于确认。首次应用这些设置需要关闭旧模拟器并重新运行脚本。脚本启动新模拟器时需保持终端打开，关闭模拟器窗口后脚本结束。

## 超分端到端回归

先启动模拟器并安装当前 APK，再从仓库根目录执行（需要完成 `npm run desktop:setup` 的 GPU 处理环境）：

```bash
node android-tv/scripts/check-super-resolution.mjs
```

脚本仅操作 `emulator-5554` 上的 `LibreTV-TV-API30`。它用 FFmpeg 生成合成片，通过真实片源 HTTP 接口、FSRCNNX/Vulkan、H.264/AAC 编码和 Media3 播放，核对 360P/480P/720P/1080P 升档、原生 4K 保持、宽屏比例、29.97 FPS、无音轨、广告分片过滤、播放中切换超分、重启保存开关及缓存隔离。冷快进完成后记录连续播放推进和缓冲样本；能出画面不代表所有输入均能实时处理。

测试使用临时端口、配对码和独立缓存，不占用现有 8090 服务。结束时恢复模拟器的设置、片源与观看/搜索记录，并清理临时转发。报告及截图保存在忽略目录 `.desktop-server/super-resolution-emulator.json`、`.desktop-server/sr-emulator-*.png`；恢复备份为 `.desktop-server/sr-emulator-backup.json`，其中含私有设置，不应分享或提交。测试期间请勿同时操作模拟器。

持续播放对比可用 `node android-tv/scripts/check-super-resolution.mjs --performance --seconds 60 --report .desktop-server/sr-performance.json`，分别采样 720P → 1080P 冷快进后及 1080P → 4K 的播放推进、缓冲、缓存余量和解码丢帧。缓冲采样为零也可能出现画面/进度停顿，需结合逐次样本判断。

## 串流缓冲优化（0.4.6）

电脑端默认准备约 8 秒视频后开始播放，并预取之后约 32 秒（默认每段 8 秒）；取流与 GPU 编码重叠，合并 FSRCNNX 模式的音频与视频编码步骤，实际请求的分片会优先于后台预取。采用有上限的 VBR 编码，24/30 FPS 的 1080P 目标/峰值为 5/8 Mbps、4K 为 12/20 Mbps；高帧率适当增加，短分片平均码率可能受 VBV 缓冲影响而暂时高于峰值参数。缓存版本更新，旧编码产物不会混用。

App 电脑增强模式采用更充足的起播与再次缓冲阈值，增加缓冲稳定性；首次等待可能多几秒。原有界面、开关和默认升一档策略保留。调试状态新增解码器名称、渲染/丢帧计数，便于区分处理等待与解码问题。更新电脑端后需重启 8090 服务，并覆盖安装新版 APK。

## 超分开关与来源缓存（0.4.3）

首页进入“片源管理”可切换“AI 超分（电脑串流）”；电脑串流播放时也可从“设置 → AI 超分”切换并按原片进度重新准备。开启默认升一档，关闭保持原始分辨率；去广告独立控制，设置自动保存。需同时运行新版电脑服务。

换源列表近期结果直接从本地显示，过期后后台刷新，按“刷新来源”可立即重新检测。搜索结果缓存 10 分钟，换源结论缓存 5 分钟，重启应用仍可复用。缓存有容量上限，不能保证被淘汰或源配置变更后的条目仍命中。

### 夹杂广告识别与学习（0.4.8）

开始播放前，数据页读取播放列表，把它按 DISCONTINUITY 或分片目录变化切成段组，对 3 分钟以内的段组各读约 64 KiB 前缀（AES-128 先解密）：

- **编码比对**：轨道布局和视频尺寸与正片主体不同、且不超过 90 秒并不超过全片 15% 的段组自动删除。只比较能完整解析的 H.264 TS / fMP4 特征，解析不全时不做判定。
- **重复插入**：同一非正片目录、时长完全相同（≤60 秒）的短段组出现两次以上即删除，不需联网，可识别与正片同编码的轮播广告。
- **广告学习**：播放设置新增「广告学习」行。广告播放时选择「标记当前片段为广告」，记下该段前缀指纹（以及非正片目录、编码特征和时长），并从广告结束处重新打开。之后同一广告文件出现在其他影片或其他目录也会自动删除。「清除已学习」可清空，学习库最多 300 条，只存在设备本地。

分析最多等待 5 秒，失败或超时只少删，不阻塞播放。盗链站会按请求动态插入广告（同一地址连续读取，有的带广告、有的不带），因此直连时 Media3 直接使用分析时读到的同一份媒体列表原文（10 分钟内有效），删除行与分析结果一致。删除在 Media3 播放列表解析器中执行，回报原片时间轴上的删除区间；进度一律按原片时间保存，播放标注显示实际删除的处数、秒数和来源。删除分片后，未写 IV 的 AES-128 片段会钉住原媒体序号，避免解密错位。电脑增强模式下，设备把识别结果连同常规启发式结果一起交给电脑（`adSegments`），修复了此前电脑串流过滤少于直连的问题；使用独立音轨的片源仍只用电脑自身规则。

真实片源验证（模拟器，2026-11-09）：6 部热门影视、约 20 个来源、70 集。被删除的段经抽帧核对全部为同一类博彩广告，未见误删正片；360 资源每集插入 3–10 段 17.6 秒广告，改进后全部识别（编码比对 + 重复插入），爱奇艺资源的单段插入由原有启发式删除。Media3 实际播放跨过删除点继续，无报错。

能力边界：广告必须是独立的分片段。与正片编在同一段、画面内的水印和滚动字幕仍无法去除。

模拟器检查（合成 720P 正片 + 360P 插入段 + 同编码插入段，备份并恢复设置、学习库与记录）：

```bash
node android-tv/scripts/check-ad-analysis.mjs
```

### 多来源比对与去水印（0.5.0）

这两项需要电脑服务（`npm run desktop:server`，更新后需重启 8090 服务），独立直连本身不变。

**多来源比对（夹在正片编码里的广告）**：「片源管理」填好电脑地址与配对码且去广告开启时，开始播放后设备在后台搜索同一片名的其他来源，取集数一致、优先不同 CDN 主机的同一集（最多 2 个），交给电脑做音频比对。电脑解码几秒音频、计算频带能量差分特征，用二分法定位两个来源时间偏移的跳变，只在当前来源出现的片段即为插入段；再用逐帧相似度精确到约 0.1–0.5 秒。两个参考都可用时只保留两边一致的结果。Media3 播放到该区间即跳过（直连与电脑串流都生效），结果在设备缓存 7 天，并在看当前集时预先比对下一集。没有其他来源、来源不是同一剪辑或音频差异过大时不跳过。

**去水印（电脑串流）**：电脑在全片 10 个位置各抽两帧灰度小图，固定台标/水印按「各场景同一位置都有边缘且图案一致」识别，用 delogo 插值；滚动广告字幕按「上下边缘横条匀速水平平移」识别，整条重度模糊。逐句变化的对白字幕不会被识别。结果按片源缓存。开关在「片源管理」和电脑串流时的「设置 → 去水印」，默认开启；标注显示实际处理的处数。抹除处会有模糊痕迹，不能恢复被遮挡的画面。

检查（需 GPU 电脑处理环境）：

```bash
node desktop-server/check-compare.mjs
node desktop-server/check-overlay.mjs
node android-tv/scripts/check-desktop-ads.mjs
```

真实片源比对（本机电脑服务，2026-11-09）：《狂飙》360 对艾旦（不同编码）未报告任何插入；《唐朝诡事录》360 对艾旦找到 1 段 17.57 秒插入，与 360 资源注入的 17.6 秒广告一致；同源镜像（光速对豪华）无差异。每次比对约 20 秒–4 分钟，取决于两个来源的差异和网络；部分 CDN 拒绝电脑直连（403/TLS 中断）时比对失败、不跳过。

第三项在模拟器上用两个本地片源与本机电脑服务端到端验证：直连时自动比对并跳过 150 秒处的 20 秒夹带广告，电脑串流时标注「去水印：已处理 台标/水印 1 处、滚动字幕 1 条」且同样跳过；结束后恢复模拟器数据。去水印对比帧保存在 `.desktop-server/overlay-before.png`、`overlay-after.png`。

**投影仪实测（JMGO K310，2026-11-10，0.5.0）**：覆盖安装后 IndexedDB、Local Storage、偏好设置 31 个文件与升级前完全一致。直连真实片源：《流浪地球2》360 删除 10 处共 175 秒、《唐朝诡事录》360 删除 3 处 52 秒、《狂飙》爱奇艺删除 1 处 17 秒，Media3（OMX.MS.AVC）跨删除点连续播放、无丢帧。电脑串流：起播 12–22 秒，快进后连续播放无丢帧；《狂飙》爱奇艺源顶部的博彩滚动字幕被识别，只在广告出现的分段模糊（逐段检测平移、按实际字高处理），无广告的分段保持原画；《唐朝诡事录》无叠加物、未处理。多来源比对在投影仪上完成过（《唐朝诡事录》52 秒、《狂飙》未发现夹带广告）；多个参考 CDN 对电脑返回 403/404/证书过期时比对失败、不跳过。

实测发现电脑若经代理（如 Mihomo TUN）以境外 IP 出网，不少国内片源 CDN 会对电脑返回 403，而投影仪直连正常；电脑串流、超分和多来源比对都依赖电脑能直连片源，需让电脑服务（node 进程）或国内视频域名走直连。另外部分片源的分片地址按请求 IP 签名，电脑使用设备分析过的列表被拒时，会自动改用自己下载的列表重试。

### 按码率自动选源（0.5.1）

遥控器在多来源的影片卡片上按确认键时，先比较各来源的实测码率，播放码率最高的可用来源（同码率比分辨率），并提示所选来源与码率；只有一个来源时直接播放。码率只读分片大小（`Range: bytes=0-0` 的 Content-Range，或 BYTERANGE），取全片 30%/50%/70% 处的分片，不下载视频内容。焦点在卡片上停留 0.8 秒即开始预探测；确认时最多等 6 秒，未测完的来源继续在后台探测并缓存 6 小时，下次直接使用。换源列表同分辨率时按码率排序，画质标注显示码率（如「1080P · 2.5M」）。

投影仪实测《狂飙》27 个来源：立刻确认时 6 秒内测完 6 个，选中 720P · 1.2M；在卡片上停留后确认，12 个全部比较，选中 1080P · 2.5M。码率越高画面越好，但对慢速 CDN 也更容易缓冲，卡顿时可在播放中换源。

直连模式不做画面去水印/遮挡滚动字幕（需电脑串流）。
